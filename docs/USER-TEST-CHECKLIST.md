## 0. 开始之前（请务必先做）

- [ ] 安装 **MaLiLib 0.28.12**（必需）。Litematica 与 QuickShulker 可选。
- [ ] **在配置界面「调试」页把 `debugLogging` 打开。** 这一步非常关键：出问题时日志能直接定位到原因，
      否则我只能靠猜。日志路径：`.minecraft/logs/latest.log`。
- [ ] 若之前测过旧版本,**删掉 `config/sortnstock.json`** 让它重新生成。
      （原因：已保存的配置值**永远覆盖**代码默认值。旧文件里可能残留已删除或已改名的键。）

### 出问题时请附上这些日志行

| 时机 | 应出现的日志 |
|---|---|
| 每次整理 | `sort: region has N slot(s), key=..., merge=..., compact=...` |
| 整理开始 | `sort: starting N click group(s), M skipped pair(s)` |
| 无事可做 | `sort: nothing to do (ALREADY_SORTED / UNREACHABLE)` |
| 补货触发 | `restock: main hand shrank (consumed minecraft:xxx), checking` |
| 用光后补货 | `restock: 'minecraft:xxx' was used up (have 0, threshold 0), refilling` |

> `region has N slot(s)` 是最有用的一个数字：**整理背包时应为 27**（不是 36，更不是 41），
> 整理大箱子时应为 54。

## 4. 整理

### 4.1 基本行为

- [ ] 悬停箱子槽位整理**箱子**；悬停主背包槽位只整理**主背包**。
- [ ] 整理开始时有原版按钮音效；无可整理内容时也有音效（音调略低）。
- [ ] 六个排序键均可用：注册名、显示名、数量、耐久、NBT / 组件、标签。
- [ ] **排序方向选项已删除**，所有排序均为顺向；「整理」页不应再出现「升序 / 降序」。
- [ ] 「合并堆叠」开 / 关。
- [ ] 「物品向前紧凑排列」开 / 关。
- [ ] 开启 `debugLogging` 后能看到 `sort: region has N slot(s)` 与 `sort: starting N click group(s)`。

### 4.2 ⚠️ 快捷栏永不被整理（写死行为，无配置项）

- [ ] 整理玩家背包后，**快捷栏 9 格的物品与顺序完全不变**。
- [ ] **盔甲槽**（头盔 / 胸甲 / 护腿 / 靴子）内容不变。
- [ ] **副手**物品不变。
- [ ] 悬停**快捷栏槽位**按整理键时，快捷栏同样不被整理。
- [ ] 日志中 `region has` 应为 **27**（不是 36 或 41）。

### 4.3 ⚠️ 合并：不得卡死，且必须填满

> 曾经的现象：**物品完全没排序 + 游戏直接卡死**。构造条件：同种物品三个以上部分堆叠。

- [ ] 箱内放 **30 + 40 + 10** 个同种物品（合计 80，超过一叠），开启合并后整理 ——
      **游戏不得卡死**，应瞬间完成，结果为 **64 + 16**，总数仍为 80。
- [ ] 再测 **40 + 40**（恰好溢出一次）→ 应为 **64 + 16**；**32 + 32**（恰好一叠）→ 应为 **64 + 空**。
- [ ] 日志中**不应**出现 `merge phase stopped at its safety bound`。
- [ ] 关闭「合并堆叠」后，上述堆叠**保持原样**，不得被强行合并。

> 另一个曾经的现象：堆叠停在半满（50 + 60 没有变成 64 + 46）。

- [ ] 箱内放 **50 + 60** 个同种物品，开启合并后整理 —— 结果必须是 **64 + 46**。
- [ ] 再测 **10 + 50 + 50** —— 结果应为 64 + 46。
- [ ] **一组 16 的物品**（鸡蛋 / 雪球 / 末影珍珠）应补到 **16**，不是 64。

### 4.4 ⚠️ 物品必须靠前紧凑排列

> 曾经的现象：整理后物品仍稀疏散布（这是配置持久化导致默认值未生效）。

- [ ] **不要改任何配置**，整理一个零散摆放的箱子 —— 物品应**紧靠左上角连续排列**，中间不留空槽。
- [ ] 同种物品有多叠时（如 64 与 46），按数量排序**大叠在前**，不得错位。
- [ ] 若想要「就地重排、保留空槽」，把「物品向前紧凑排列」关闭，确认空槽确实被保留。

### 4.5 ⚠️ 潜影盒放进**容器的最后几格**

> **换 jar 之后必须完全退出并重启游戏。** 只覆盖 `mods` 里的文件不会生效，
> 游戏会继续使用启动时加载的旧版本。

规则：潜影盒占据**整个容器的末尾槽位**，其余物品紧凑排在前面，两者之间可以留有空格。

以 27 格箱子、12 组普通物品、9 个潜影盒为例：

| 槽位 | 内容 |
|---|---|
| 0 – 11 | 普通物品（紧凑排列） |
| 12 – 17 | **空格（间隙）** |
| 18 – 26 | **9 个潜影盒** |

- [ ] 箱内放入普通方块 + **多个潜影盒**（至少含一个染色潜影盒），整理后潜影盒应在**最末几格**
      （如 27 格箱子的 18–26），而不是紧跟在普通物品后面。
- [ ] 潜影盒与普通物品之间**应留有空隙**（除非箱子已装满、放不下间隙）。
- [ ] 切换排序方向为**降序**后再整理 —— 潜影盒**仍然在最末几格**（不得跑到最前面）。
- [ ] 换几个排序键（注册名 / 数量 / 耐久等）重复确认，潜影盒始终在末尾。
- [ ] 只放 1 个潜影盒时，它应在**最后一格**（27 格箱子的第 26 格）。
- [ ] 数量边界：把箱子塞到几乎满（普通物品 + 潜影盒占满 27 格），潜影盒仍应在末尾且**无物品丢失**。
- [ ] **日志自证**：开启 `debugLogging` 后，日志应出现
      `sort: live shulker slot(s) = [...]` 与 `sort: target shulker slot(s) = [...]`。
      27 格箱子 9 个潜影盒时，target 应为 `[18, 19, ..., 26]`。若与此不符，请把两行都发我。

#### 盒子组内部的顺序（末尾块里从左到右）

优先级：**1 > 2 > 5 > 3 = 4**

1. **填充状态**：空盒 → 未满盒 → 满盒
2. **颜色**：创造栏颜色顺序（白、橙、品红、淡蓝、黄、绿、粉、灰、淡灰、青、紫、蓝、褐、绿、红、黑）；无色普通潜影盒排在最前
5. **杂盒在纯净盒前**（含两种以上物品 = 杂盒；只有一种 = 纯净盒）
3. **不满盒：内容物最少的在前**
4. **满盒：按内容物首位排序，顺序与普通物品一致**

- [ ] 同时放入**空盒、部分装满的盒、完全装满的盒**，整理后空盒在前、满盒在最后。
- [ ] **优先级 1 > 2 检验**：一个「空的黑色盒」+ 一个「满的白色盒」—— 空的黑盒必须在前。
- [ ] **优先级 2 > 5 检验**：一个「纯净的白盒」+ 一个「杂色的黑盒」—— 白盒必须在前。
- [ ] **杂盒在纯净盒前**：同为不满、同色的两个盒子，装两种物品的排在只装一种之前。
- [ ] **不满盒按内容物多少**：同为不满、同色，装的少的在前。
- [ ] **满盒按内容物首位**：两个满盒按各自第一格物品、以普通物品的排序键比较。
- [ ] 「满盒」判定：**27 格全占满、且每叠都达到自身上限**才算满；每格只放 1 个应算「未满」。

> **已确认的实现细节**（用户已于 2026-10-19 确认）：
> - 「内容物最少」= 盒内**物品总数量**最少；
> - 「满盒按内容物首位」= 盒内**第一个非空格子**的物品；
> - 空盒没有内容物，一律视为「纯净盒」——因为所有空盒都同为纯净，实际对排序无影响。

### 4.6 ⚠️ 创造模式下中键优先复制选取

- [ ] **创造模式**下，鼠标悬停**有物品**的槽位按中键 → 应执行原版**复制/选取方块**，**不触发整理**。
- [ ] 同一界面悬停**空格子**按中键 → 应执行**整理**（此时原版复制无动作，故让位给整理）。
- [ ] **生存模式**下中键仍应正常触发整理（不受此规则影响）。
- [ ] 把整理键**改绑**为非中键（如 `F6`）后，创造模式下 `F6` 应照常整理。
- [ ] 开启 `debugLogging` 时，创造模式悬停有物品的槽位按中键，日志应出现
      `sort: creative pick-block takes priority, not sorting`。

### 4.7 安全性与边界

- [ ] **不丢失、不复制、不替换任何物品** —— 请仔细比对整理前后的数量。
- [ ] 光标上持有物品时整理箱子，应为**安全空操作**。
- [ ] 整理已排好序的容器，应为空操作（仅音效，无动作）。
- [ ] 接近满的背包也能整理尽可能多的物品，而不是完全无动作。
- [ ] 容器内存在**同种物品、不同数量**的两个堆叠并按「数量」排序时，能正常整理（排不了则跳过该对，不整体放弃）。

### 4.8 单 tick 全量下发（服务端兼容性）

整理的整套点击会在**一个 client tick 内全部发出，没有节流**。请重点验证真实服务器上的表现。

- [ ] 整理一个**很大的容器**（27 格箱子几乎装满不同物品）能否一次完整整理到位。
- [ ] 整理后**物品数量与整理前完全一致**，**光标为空**，**没有物品跑到错误的容器里**。
- [ ] 严格服务器（反作弊 / 数据包限流）：大整理是否被踢出、被回滚，或出现客户端与服务端不一致。
- [ ] 若服务端拒绝中间某次点击：观察是否排列错乱；**确认物品仍未丢失**。

## 5. 自动补货

默认**关闭**，需在配置界面手动开启（**已无快捷键**）。

### 5.1 基本行为

- [ ] 开启后，快捷栏中低于 `restockMinCount` 的物品被**一次补满一组**（多数物品为 64）。
- [ ] **按物品自己的上限补满**：鸡蛋 / 雪球 / 末影珍珠（一组 16）应补到 **16**。
- [ ] `restockMinCount` 可调到 **0** 与 **64**。
- [ ] 目标槽位：快捷栏 / 副手 / 两者。
- [ ] 玩家背包与已打开容器**恒定可作为来源**（已移除它们的开关）。
- [ ] 冷却与每 tick 操作上限能限制操作频率。
- [ ] 跨「玩家背包 / 潜影盒 / 已打开容器」搬运时**无复制或丢失**。
- [ ] 光标上持有物品时，自动补货绝不执行。

### 5.2 ⚠️ 最小值 = 0：用光后必须补货，且补回**原来那一格**

> 曾经的现象：用光后毫无反应（格子空了就认不出原来是什么物品）。
> 修好之后又出现过：补货落到**第一个空格**，而不是刚用光的那一格。

**请把方块放在非第一格的快捷栏格（例如第 5 格）来测，否则看不出问题。**

- [ ] `restockMinCount` 设为 **0**，快捷栏第 5 格放一组方块。
- [ ] 一直放置直到手中方块**完全用光**（该格变空）。
- [ ] **空手之后应立刻自动补满一组**。
- [ ] **补货必须回到第 5 格**，不得跳到第 1 个空格。
- [ ] 在**快捷栏有多个空格**的情况下重复上一步，确认不会跑到别处。
- [ ] 同一物品在快捷栏有两叠（第 2 格与第 7 格），从**第 7 格**用完 —— 应补回**第 7 格**。
- [ ] 手中有 5 个方块时（未用光）**不应**触发补货。
- [ ] 日志中出现 `main hand shrank (consumed minecraft:xxx), checking` 与
      `'minecraft:xxx' was used up (have 0, threshold 0), refilling`。

### 5.3 ⚠️ 触发时机与反向确认

- [ ] **唯一触发**：手持方块右键放置后、手持食物 / 投掷物使用后，数量减少时触发检查。
- [ ] **反向确认**：单纯拾取物品、打开容器、站着不动，**不会**触发补货检查。
- [ ] **反向确认**：切换快捷栏格子（从大堆叠切到小堆叠）**不会**被误判为「数量减少」。
- [ ] 一组 = 1 的物品（工具等）**不参与**按数量补货（刻意行为；若希望它们也被补到 1，请告知）。

## 6. 潜影盒联动（独立标签页）

- [ ] 「潜影盒联动」标签页存在，且**只有 1 项**：`quickshulkerRestockFromShulker`（从潜影盒中补货）。
- [ ] 关闭「从潜影盒中补货」时，用完物品后**不会**去开盒子补货。
- [ ] 开启时：把所需物品放进**背包里**的潜影盒（非快捷栏），用完手持那一叠 —— 应**自动打开该盒子并补满手持槽**。
- [ ] **补货完成后盒子应自动关闭**，且关闭时机应在物品已到背包之后（不应出现「界面先消失、声音后到」）。
- [ ] **关键：不应出现「幽灵物品」** —— 关盒前后背包内物品数量必须一致。
- [ ] 补满的应是**当前所选的那个快捷栏格子**，而不是第一格。
- [ ] 注意：盒子界面会**真实弹出**（取出物品必须开盒，QuickShulker 只提供开盒接口）——平台限制，无法静默完成。
- [ ] 若物品所在盒子在快捷栏/副手，同样应生效。
- [ ] **已安装 QuickShulker**：仅存在于携带潜影盒中的物品能触发开盒请求，并在盒子打开后完成补货。
- [ ] **未安装 QuickShulker**：潜影盒来源不贡献任何内容，且不崩溃。
- [ ] 两种情况下读取潜影盒内容均正常（内容通过原版组件读取）。
- [ ] 为补货而开盒的行为在您不希望时不会造成干扰。

## 7. 投影联动（需要 Litematica）

默认**关闭**，需手动开启。

- [ ] **未安装：** 完全不触发，无日志刷屏，无崩溃。
- [ ] **无激活投影 / 准星未指向投影方块 / 该位置无方块：** 均不触发。
- [ ] **主手为空，右键投影位置：** 是否触发补货？
- [ ] **主手物品错误，右键：** 是否触发补货？
- [ ] **主手物品正确但数量低于 `restockMinCount`，右键：** 是否触发补货？
- [ ] 投影联动复用补货的 `restockMinCount`（无投影专用阈值）。
- [ ] 修改 `restockMinCount` 后，联动立即使用新阈值。
- [ ] 配置界面「投影联动」页**恰好 4 项**（开关 / 缺料时从潜影盒取用 / 数量不足补货 / 冷却）。
- [ ] 修改 Litematica 的 `pickBlockableSlots` 后，目标槽位同步生效。
- [ ] `pickBlockableSlots` 限制为子集（如 `"1,2"`）→ 补货只用这些槽位。
- [ ] `pickBlockableSlots` 设为空（`""`）→ 补货被跳过且无报错。

### 7.1 ⚠️ 时序问题（重点）

预期时序：`SortNStock 补货 → Litematica Pick Block → Easy Place`。

- [ ] **触发的那一次右键是否真的用补货后的物品完成了放置（一次点击内）？**
- [ ] 若**无法**一次生效，请确认**二次右键**是否有效 —— 若如此，文档必须标注「本次右键可能不生效，需二次右键」。
- [ ] 补货后 Pick Block 是否切到正确物品？Easy Place 是否正常放置？
- [ ] 右键是否仍正常传递（未被拦截或取消）？
- [ ] 确认 SortNStock **不会**自动放置、自动搭建或修改投影。
- [ ] 在 `easyPlaceSwapInterval` / 「easy place too fast」附近交互，回馈补货是否使其恶化。

## 8. 稳定性与多人环境

- [ ] 单人**生存**基础可用。
